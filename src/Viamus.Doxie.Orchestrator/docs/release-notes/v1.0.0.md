# DoxieOS 1.0.0

DoxieOS 1.0.0 is the first stable release of the local agent workspace. It turns a developer machine into a provider-neutral control plane for agents, skills, libraries, workflows, consoles, run history, synapse-style collaboration, and generated provider shims.

## From v0.1 to 1.0

The biggest change is architectural: DoxieOS no longer treats one CLI layout as the product. The canonical layer is now `.doxie/`, and provider-specific folders such as `.claude/` and `.codex/` are generated outputs. That gives DoxieOS one source of truth while still supporting the tools developers actually run every day.

The release also expands Doxie from a launcher into a working environment: richer agent metadata, multi-provider execution, persisted run usage, workflow primitives, library browsing, Symbiosis spaces, and faster high-volume run pages.

## Provider-neutral runtime

Agent execution now goes through an `IAgentProvider` layer. Claude Code remains supported, and OpenAI Codex can be selected in Settings. DoxieOS adapts command resolution, prompt assembly, interactive console arguments, and usage estimation per provider.

Codex support includes Windows command resolution, neutral prompt headers for slash-command-shaped skills, inline skill bodies, subcommand body loading, execution directives, optional approval bypass for runs, and YOLO mode for Codex consoles so interactive sessions match Doxie-owned agent trust boundaries.

## Doxie canonical authoring

The source of truth moved to `.doxie/`:

```text
your-project/
  .doxie/
    skills/<id>/manifest.json
    skills/<id>/body.md
    skills/<id>/memories/*.md
    agents/<id>.md
    libraries/<id>/...
  .claude/
    skills/<id>/SKILL.md
    agents/<id>.md
    libraries/<id>/...
  .codex/
    AGENTS.md
```

The shim pipeline is idempotent, content-aware, and orphan-safe. It rewrites only changed bytes, watches `.doxie/` with a debounce, and cleans up only folders marked as Doxie-generated. Settings now stays focused on runtime configuration and storage paths instead of exposing codegen controls.

## Skill memories

Skills can load dispatch-time memories from `.doxie/skills/<id>/memories/*.md`. Each memory can declare priority and a small condition expression in frontmatter, so provider-specific, mode-specific, or workspace-specific guidance can be injected without bloating the main skill body.

Claude Code and Codex receive the same delimited context block. Agent Detail shows configured memories with priority chips and a shortcut to open the memory folder.

## Agents and categories

Agents gained stronger catalog metadata, search, custom categories, and safer category editing. Editable agents can now choose a persisted icon, so category changes no longer force every agent in a group to look identical.

The builder path is provider-aware, writes drafts into a sandbox, and can retro-feed useful memories into agent and workflow builder skills.

## Cost and token tracking

DoxieOS records Claude usage from terminal result events and persists input tokens, output tokens, cache-read tokens, cache-creation tokens, total cost, and provider id per run. History and Agent Detail show the breakdown, and Home includes spend totals for 24h, 7d, and all time.

Codex runs now report meaningful simulated usage and cost estimates even when the CLI does not emit structured billing events. Synapse pulses also preserve provider usage so collaborative runs no longer appear as zero-token executions.

## Synapse and Symbiosis

The Symbiosis workspace introduces multi-agent collaboration spaces. Runs can be grouped by pulse, routed through agent decisions, summarized per wave, and inspected through a compact final report.

Prompt assembly was hardened for long Synapse iterations. Prior pulse context is now written through bounded temporary prompt files when needed, avoiding command-line length failures on Windows while preserving the collaborative memory of earlier pulses.

## Workflows

Workflows gained loop primitives, disabled-by-default cron workflow creation, better run path handling, and additional workflow tests. This makes repeatable agent orchestration safer for local automation without turning every new schedule on immediately.

## Libraries and workspace files

Libraries gained a file-tree browsing experience with inline markdown viewing, single-memory copy and download, uploads, zip export, and zip import. Workspaces align library mounting with provider context so agents can consume the same curated knowledge regardless of the selected CLI.

## Faster dashboard and log loading

Large application logs no longer block common page transitions. History and Agent Detail list run metadata without hydrating every output line, and selected runs load only the latest visible console tail. Heavy output fetches render behind a spinner.

The dashboard renders immediately and loads expensive run, spend, cron, and recent-activity snapshots in the background. Activity events are debounced through a single reload worker, and the sparkline no longer depends on chart JS interop.

## Upgrade notes

Existing SQLite databases are migrated in place. New nullable columns are added idempotently to `agent_runs`, and older rows continue to render with unavailable usage values until a new run records provider usage.

Existing `.claude/` assets remain untouched. DoxieOS reads from `.doxie/` at runtime, and provider shims are regenerated from that canonical layer.
