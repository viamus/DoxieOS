# DoxieOS 1.1.0

DoxieOS 1.1 is the first stable catalog release after 1.0. It turns the local workspace into a shareable agent operating layer: agents, workflows, and libraries can now live in Doxie catalogs, libraries can move across machines cleanly, workflow outputs have stronger contracts, and the product shell is focused on explicit execution surfaces.

The headline change from 1.0 is ownership. DoxieOS still ships its first-party catalog, but users can now keep their own agent and library repositories on disk, point DoxieOS at those folders, and share the same catalog with another machine or teammate without copying everything into the product folder.

## Doxie catalogs

Settings now supports custom Doxie catalogs. A catalog is a folder that can contain Doxie agents, workflows, and libraries using the same canonical shape as the default `.doxie/` catalog.

Agent and workflow creation now asks for a destination catalog. Libraries can be imported into a selected catalog through a modal, and the UI filters agents, workflows, and libraries by catalog so it is clear where each asset lives.

The old private-agent flag is gone. Private work now belongs in private folders such as `.private/`, while shareable work belongs in a catalog repository.

## Interface polish

The app shell has a more professional chrome: tighter top bar, cleaner drawer behavior, a subtle footer, shared page surfaces, refined dashboard panels, and a more deliberate active navigation state.

The mini drawer now keeps icons centered, while the expanded drawer gives active items enough left padding so the Tigerlily indicator does not collide with the icon.

The Home dashboard now keeps the agent inventory compact by showing only the leading category counts and preserving the full breakdown in hover text.

## Doxie icon refresh

DoxieOS now uses the Doxie mark consistently in the app chrome, favicon, and install manifest.

The previous assistant surface and its knowledge graph services were removed. DoxieOS now focuses on explicit agents, workflows, workspaces, libraries, consoles, run history, and notifications.

## Agent icon picker

Agent Detail and the Agent Builder now use a searchable icon picker instead of a tiny menu. The picker supports a curated Material icon palette, search by label or key, preview, apply, and reset-to-category-default.

The icon allowlist is centralized so the list page, detail page, builder preview, API validation, and persisted manifests all agree on the same supported icon keys.

## Doxie core kit

DoxieOS 1.1 ships a compact first-party set of Doxie-native skills for authoring agents, authoring workflows, creating reusable libraries, composing workflow primitives, and managing temporary sandboxes.

These are not copied third-party packs. They are Doxie-native building blocks shaped into consistent inputs, outputs, validation checks, and handoff sections that workflows can consume.

The public kit is intentionally small. Domain-specific catalogs can live in separate private repositories, while this repository keeps only the core Doxie standards needed to bootstrap a clean installation.

## Workflow templates

DoxieOS 1.1 favors a smaller set of outcome-driven workflow templates over a large gallery of similar patterns. The public repository keeps the workflow primitives and builder flow, while specialized templates belong in separate catalogs.

These workflows deliberately chain broader agents: transform, aggregate, loop, approval, and workspace output. The goal is fewer choices, clearer intent, and more useful automation for day-to-day developer work.

## Workflow output contracts

Workflow node prompts now receive stronger guardrails around `DOXIE_WORKFLOW_OUTPUT_DIR`. Agents are told to write durable files into the workflow output folder, to produce a meaningful `output.md` even when the result is blocked, and to avoid treating terminal text or stdout as the durable handoff.

This makes downstream workflow nodes more reliable and sets up DoxieOS 1.2 work on richer notifications that can show useful markdown, HTML, and generated artifacts from the run.

## Contextual recommendations

Agents and Workflows now include a contextual recommendation action. Type the problem or goal, then ask DoxieOS to suggest the most relevant agents or workflows from the local catalog.

The recommender is intentionally local in this release: it ranks catalog metadata by context match, so it works without external credentials while still helping users navigate a 50+ agent workspace.

## Safer orchestration handoffs

Large agent invocations are now materialized into `.doxie/run-inputs/*.md` and passed by reference before they hit provider command-line limits. This protects workflow handoffs from Windows "command line too long" failures while preserving the full prompt payload.

Workflows with an attached workspace now use that workspace as the default cwd for every agent node that does not override it. The orchestrator runner also wraps each dispatch with the workspace's `WORKSPACE.md`, local `memory/*.md`, and mounted library memories, so iterative workspace context travels through workflows without editing every individual agent.

Running agents and workflows now accept live operator hints from the detail pages. Doxie records each hint in the run log, appends it to `DOXIE_OPERATOR_HINTS_FILE`, forwards it to providers that support live stdin sessions, and carries accumulated workflow hints into downstream node prompts.

The workflow detail header actions now keep stable button dimensions during active runs, avoiding the oversized action buttons that could appear while live status updates were streaming.

The Home dashboard no longer shows the "failed runs in the last 24h" callout; failures remain available in History without turning the dashboard into an error wall.

## History cleanup

History now has a clear execution history action that removes persisted agent and workflow runs from the local state database. This gives long-lived workspaces a quick way to reduce local cache noise without deleting agents, workflows, or workspaces.

## Libraries

Library authoring is now part of the core Doxie kit, so users can turn files or existing memory folders into reusable memory packs with consistent metadata.

No domain library ships in the public repository by default. Shared or private memory packs can be added through external catalogs when a team needs them.

## Builder safety

Agent edit sessions now preserve custom category labels and existing icon choices. The builder can update only the draft icon through a narrow endpoint, leaving the AI-authored manifest text as the source of truth for everything else.

Icon validation also runs during manifest promotion, so invalid icon keys are caught before Save instead of silently falling back at render time.
