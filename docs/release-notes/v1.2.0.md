# DoxieOS 1.2.0

DoxieOS 1.2.0 is the operational visibility release for local agent work.

## What Changed

- Notifications can now carry output previews from agent and workflow artifacts.
- Agent and workflow completion notifications link directly to their run detail pages.
- Markdown, HTML, JSON, YAML, log, and text artifacts can appear inside the notifications page.
- Docker Compose support was added with separate volumes for state, workspaces, runs, and sandboxes.
- Docker Compose publishes DoxieOS on host port 6034 by default to avoid colliding with local development on 5034.
- Docker Compose now persists provider `$HOME` so Claude Code and Codex auth can survive container recreation.
- Settings now shows provider auth status and can open provider-specific auth consoles.
- Settings now includes an MCP registry that writes Claude `.mcp.json` and Codex `~/.codex/config.toml`.
- Settings imports MCP servers already present in Claude/Codex global configs into the durable Doxie registry.
- Agent console output and workflow node logs now use a roomier structured viewer with line numbers, source labels, clearer spacing, and inline search highlighting.
- Server-side API request logging now records endpoint start, completion, status code, and duration.
- Notification ingestion and read-state changes now emit structured logs.
- Console logging now uses Serilog formatting without writing application logs to files.
- Agent detail history now shows live elapsed duration while a run is still executing instead of a placeholder symbol.

## Notes

The Docker image runs the DoxieOS web app and persists its runtime folders in
volumes. Provider-backed execution still needs the matching provider CLI and
credentials available inside the container.
